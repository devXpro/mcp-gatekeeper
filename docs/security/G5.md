# G5 security notes

- **Trusted peers.** `PeerGuard` deletes `CF-Connecting-IP` and `X-Forwarded-For` from every request whose TCP peer is
  not in `PeerOptions.Trusted` (or whose address does not parse), so `core.ClientIP`, rate limits and the audit never see
  a client-chosen address. IPv4-mapped IPv6 peers are unmapped before matching. With no trusted prefixes nothing is
  believed. Order matters: `PeerGuard` must run before anything reads the client address; `New` puts it right after
  `RequestLog` and `Recover`. An application that builds its own chain keeps that order.
- **Request log.** One line per request with method, mux route pattern, status, bytes, duration, client address. It never
  has the raw path, the query string (OAuth codes, states, transaction ids), a header or a body; unmatched requests log
  `(no route)`. No `Authorization`, no cookies. Tested with planted secrets.
- **Recovery.** A panic answers `500 {"error":"internal"}` (when the answer has not started) and logs the panic value and
  stack; the stack goes to the log only, never to the client. `http.ErrAbortHandler` is re-panicked.
- **Pages.** `SetSecurityHeaders`: the application's CSP, nosniff, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`,
  HSTS (one year, no includeSubDomains/preload). COOP `same-origin` except on the routes named in `webui.Options.NoOpener`
  (the consent page, which lives in an assistant's connector window).
- **SPA handler.** Serves only a fixed set of files read at start (no filesystem access per request): dot files are never
  served, a missing `/assets/*` is a plain 404 (never index.html), top-level public files are registered only when their
  names are safe route names, and the path under `/assets/` is cleaned and joined to the in-memory table only.
- **Body limit.** `BodyLimit` refuses a declared oversize body at once and caps undeclared ones with `MaxBytesReader`.
- **Server.** `ReadHeaderTimeout` 10 s, `MaxHeaderBytes` 64 KiB, idle 2 min; deliberately no read/write timeout (SSE).
- **Cloudflare connect.** cloudflared runs with an exact environment (`HOME`, `TUNNEL_ORIGIN_CERT`, an empty-directory
  `PATH` so no browser opens), nothing of the application's environment. The account certificate lives only in a temporary
  HOME that is removed on every way out and the certificate file is deleted on success. Credentials, `config.yml` and
  `tunnel.json` are written atomically with mode 0600 in a 0700 directory. The hostname is validated against a strict
  pattern before it reaches a command line or `config.yml`; `Service` must be one line; the name prefix is
  `[a-z0-9-]`. A DNS record is replaced only with `OverwriteDNS`. No Cloudflare API token is ever read.
