# G3 — security notes for auth and adminsock

`auth` and `adminsock` are Family Hub's `internal/auth` and `internal/adminsock` moved, with the rules of Family
Hub's docs/security/T1.2.md and T2.F2.md unchanged. This note lists only what the move touched; read those two for
the whole model (secrets and what they unlock, ceremonies, sessions, limits, audit).

## Unchanged, and checked by the ported tests

- Passkeys: discoverable credentials, user verification required, no attestation, one origin (the public URL) and
  the RP ID of `core.Site`; a ceremony lives 5 minutes, finishes once, only at its own endpoint and, for step-up and
  a new passkey, only in the session that began it. Counters that go backwards and changed backup-eligibility flags
  are refused; known credential ids are refused at registration.
- Sessions: 32 random bytes in the `__Host-` cookie, only the sha256 stored, compared again in constant time; 12 h
  idle, 7 days absolute; `Secure; HttpOnly; SameSite=Strict; Path=/`. Deleting a passkey and "sign out on other
  devices" end every session of the person in one transaction and never revive or extend one.
- CSRF: every mutating route behind `RequireViewer`, `SameOrigin` or a ceremony guard needs
  `Brand.CSRFHeader: 1`, an `Origin` (when sent) equal to the public URL and `Sec-Fetch-Site` (when sent)
  `same-origin`.
- Rate limits per class and per address (/64 for IPv6) or session, no shared bucket; failed sign-ins coalesced into
  one system audit entry per address group a minute.
- Setup links and invites: 256-bit tokens in the URL fragment, stored as sha256, single use, 15 minutes and 24 hours.
- No token, cookie, link, challenge or credential in a log line or an audit entry (`TestNoSecretInLogsOrAudit`).
- The admin socket: 0600 file, 0700 directory when created, peer uid checked (own user or root; other platforms
  refuse everyone), a live socket never replaced, a non-socket never removed, arguments, stdin and output never
  logged.

## What changed with the move

- **Names come from `core.Brand`.** `New` refuses a session cookie that is not a valid cookie name starting with
  `__Host-` (and longer than it), a CSRF header that is not a header token, and an empty product. A cookie without
  the prefix would lose the host binding; a broken header name could never be sent, so every write would fail.
- **reset-access is generic.** What it ends in the application's own data comes from `Options.ResetSteps`, called for
  every superadmin inside the same transaction, after their passkeys, sessions and grants and before their invites;
  a step's error rolls the whole reset back. Family Hub must pass its legacy-key step (G9), or reset-access would
  leave the superadmin's legacy Site keys alive after a compromise. Step keys cannot shadow auth's own audit keys.
- **The command registry is shared.** Any package or the application adds commands to one `adminsock.Registry`;
  `Add` refuses a repeated name, so no package can silently replace `setup-link` or `reset-access` with its own.
  Commands may be added after `Start`; whoever can reach the socket is still the operator.
- **net/http instead of Gin.** The middlewares write the JSON error and do not call `next`; nothing after them runs.
  The ceremony guard learns about a failed finish from a per-request state in the context instead of a Gin key.
  A panic in an admin-socket handler is recovered without logging its value; `http.ErrAbortHandler` still aborts.

## Open points (for G.R)

- `IssueInviteIn(ctx, st, …)` uses the store it is given; with the transaction in the context it is now the same as
  `IssueInvite` called with the transaction's context. It stays for the method set `people.Inviter` expects.
- A wrong method on an auth path is answered by the application's mux (ServeMux: 405 with `Allow`), not by auth.
