# G7 security notes — package people

Kept from Family Hub, each covered by a test:

- **Isolation.** The account comes from the session only; no route takes an account id from the client. The
  superadmin's routes give counts, never members or data (TestNoDataPath). A connection of the application is shown
  only when its person is in the viewer's account, whatever the extension returns.
- **Guards.** NoStore → RequireViewer (CSRF first, then 401) → owner/superadmin → step-up, so refusals are
  `no-store` and a member is told "forbidden" before being asked for a passkey (TestGuards). Step-up: invites,
  removing a member, deleting the account, creating and deleting accounts.
- **Audit privacy.** A member reads only entries where they are actor or target, without other people's addresses
  (L4); the system audit drops the address of `auth.login.fail` (L9); an owner's name and address stay out of the
  system `account.delete` entry (L9); actor names come from the live store only for the viewer's own account.
- **Secrets.** Invite URLs (the token is in the fragment) are answered once and never logged or audited (TestInvites
  checks the audit and the log). Unclassified errors are logged and answered 500 `internal` without their text.
- **Delete everything.** Runs on a context the client cannot cancel; the account's rows go only after the
  application's eraser succeeded, so a failure keeps everything for a retry; the session cookie is cleared with the
  `__Host-` attributes (Secure, HttpOnly, SameSite=Strict, Path=/).
- **Bodies.** JSON objects only, `application/json`, 256 KiB cap, a single value.

New with the extension points:

- An application field that takes one of the package's names (`id`, `name`, `members`, …) is refused with 500, so
  an extension cannot overwrite the account or the member list.
- `APIError.Extra` never replaces `error` or `message`.
- `Owns(id)` routes an id to the application before the grant store; Family Hub's `lk_` ids never reach
  `GetGrant`, as before.

Open: none.
