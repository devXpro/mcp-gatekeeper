# G6 — the MCP access check (`mcpguard`): tests

## Unit tests and lint

```sh
make -C <repo> lint test PKGS=./mcpguard/...
```

Everything runs offline in about two seconds, with no Docker, no build tags and only `httptest` on 127.0.0.1.
Coverage is 98.7 % of statements (`go -C <repo> test -cover ./mcpguard/...`).
The tests were also run with `-count=5` under `-race`, and they passed each time.

The harness (`fakes_test.go`) is an application with a `net/http` mux whose only handler is
`Guard.Middleware(proxy)`. `proxy` is a small MCP proxy built only from the package's helpers, the way Family Hub's
module proxy will use them: `AccessFrom` and `PersonFrom`, `Admit`, `ReadBody`, `RequestHeaders`, a call to a fake MCP
server that records every request, `ResponseHeaders`, and `Relay`. The fakes are the token validator (with a lenient
mode that ignores the resource), the people and the resource switches. Logs go to `internal/testlog`.

## What the tests cover, by file

- `guard_test.go`, the middleware:
  - `New` checks every required option and fills in the defaults.
  - A valid call passes on POST, GET and DELETE, under a sub-path, with any letter case of `Bearer`, and with extra
    spaces. The handler sees the right `AccessInfo` and `Person`, and the answer carries the security headers.
  - The refusal table, ported from Family Hub's `TestMCPRefusals`:
    - 401 `unauthorized`: no token, another scheme, an empty bearer, a bearer with a space or a tab;
    - 401 `invalid_token`: an unknown token, a token of another resource, a disabled person, a person who is gone, a
      person in another account;
    - 403: the switch is off;
    - 404: a path outside the resources, or the bare prefix.

    Every row checks the exact `WWW-Authenticate`, the CSP, `nosniff` and a single `no-store`. Nothing reaches the
    handler or the server, and no token is in the logs.
  - `TestGuardAnswersAsFamilyHubDoes` pins the exact bytes of the 401s and the 403, including their `Content-Type`.
  - The lenient validator: the guard checks the token's resource itself.
  - Every dead-token error (`ErrInvalidToken`, `ErrNotFound`, `ErrExpired`, `ErrUsed`, wrapped) is a 401 and is not
    logged.
  - A failure of the token check, the people or the switch is a 500 `internal` with no detail in the body. It is
    logged once as `mcpguard: …`, with the resource and the error.
  - Homie's shape, `core.SingleResource{At: "/mcp", ID: "home"}`:
    - `/mcp`, `/mcp/` and `/mcp/messages` pass;
    - the `resource_metadata` is `…/.well-known/oauth-protected-resource/mcp`;
    - `/mcpx`, `/` and `/mc` answer 404.
  - A resource id that holds `"` and `,` is escaped in `resource_metadata`, so it cannot end the quoted header value.
  - The context accessors work on an empty context and with the middleware alone (`httptest.NewRecorder`).
- `limits_test.go`:
  - `Admit` gives 16 places per (account, resource). The 17th call gets 429 with `Retry-After: 1` and the exact body.
    Other accounts and resources keep their own places. A second `release` gives nothing back. In the end no counter
    is left.
  - The same through the application, with 16 held calls.
  - `TestFailureLimitPerAddress`, ported, in Cloudflare mode. Thirty failures from one IPv6 /64 mix unknown tokens,
    tokens of another resource, disabled people and a second door that refuses through `Guard.Refuse`. After them,
    every kind gets 429 with `Retry-After: 2` and no `WWW-Authenticate`. A request without a credential is no failure.
    A valid token from the spent address passes. Other addresses are not touched.
  - `TestFailureLimitRefills` and `TestAddressKey` are ported unchanged.
- `headers_test.go`:
  - The MCP 2026-07-28 routing headers (`Mcp-Method`, `Mcp-Name`, `Mcp-Param-<name>`) pass, and lookalikes do not.
    This is the test of Family Hub `b0fc38b`.
  - Only the allowed headers pass:
    - to the server go only `Accept`, `Content-Length`, `Content-Type`, `Last-Event-Id`, `Mcp-Protocol-Version` and
      `Mcp-Session-Id`, with no `Authorization`, cookie, `Proxy-Authorization`, `TE`, forwarding or other header;
    - back come only `Content-Type` and `Mcp-Session-Id`, and the server's `Cache-Control` becomes `no-store`.
  - The copies are deep and keep every value.
  - `ReadBody`: a body of exactly 1 MiB passes. A body over 1 MiB gets 413, whether `Content-Length` says so or the
    body is sent chunked. A body that cannot be read gets 400, and a nil body is fine. Through the application,
    nothing oversized reaches the server.
- `sse_test.go`:
  - The SSE state machine and `copySSE` tests are ported unchanged: the pings come only between events, every chunk
    is flushed, and the stream ends with the context, a read error or a write error.
  - New: the stream also ends on a flush error.
  - `Relay` refuses an event stream to a writer that cannot flush (`http.ErrNotSupported`); a plain answer needs no
    flush.
  - Through the application, ported from Family Hub:
    - events arrive while the server still streams, with `Cache-Control: no-cache, no-store`, `X-Accel-Buffering: no`
      and the CSP;
    - an idle stream gets `: ping`;
    - the server's status and body pass (202, 404, 400 and 405);
    - a client that goes away cancels the server's request, while it streams and before it answers.

## Family Hub tests that are not ported

These stay in Family Hub; G9 adapts them (see G9 in the report). They test what stays there: the Caller, the legacy
door, identity minting, session binding, module resolution, `cleanRest` and the `/hub/` tree, the proxy client and its
timeouts, the call log and `rpcSummary`.
