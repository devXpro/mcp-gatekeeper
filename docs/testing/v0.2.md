# v0.2 — tests

What v0.2 added to the tests, by package. The OAuth rows are in [G4](G4.md). Everything runs offline; only the MongoDB
compatibility tests need Docker (tag `integration`).

```sh
make -C <repo> lint test PKGS="./mcpguard/... ./httpsec/..."
make -C <repo> lint test PKGS="./auth/... ./adminsock/..."
make -C <repo> lint test PKGS=./people/...
make -C <repo> lint test PKGS=./store/...
make -C <repo> integration PKGS=./store/...              # a throwaway mongo:8.0 container
make -C <repo> lint test PKGS=./tunnel/...
npm --prefix <repo> run typecheck && npm --prefix <repo> run lint && npm --prefix <repo> test
```

Timing tests were repeated with `-count=5` under `-race` and the packages with `-count=3` or more, with no flakes.

## `mcpguard` and `httpsec`

- `mcpguard/guard_test.go`
  - `TestNewChecksItsOptions`: the defaults (16, 30, "module", `PerAccount`), the set options, `Site.Validate` refusals
    (no URL, plain http, empty or unknown `ClientIP`), negative caps and an unknown key.
  - `TestGuardRefusals` and the golden `TestGuardAnswersAsFamilyHubDoes`: now also a disabled person, a guest past
    their term, and the 404 bytes. The golden 401/403 bytes are unchanged with the default options.
  - `TestGuardSpeaksTheApplicationsWords`: the brand noun in the 401, 403 and 429 texts.
  - `TestGuardEndsAGuestsAccessAtTheirTerm`: with a fake clock, OK one nanosecond before `AccessUntil`, 401 (today's
    bytes) at it.
  - `TestMiddlewareForKeepsATokenToItsResource`: a probe with a path-cleaning router. `Middleware` lets a token for one
    resource reach another (the documented hole); `MiddlewareFor` answers 404.
  - `TestMiddlewareForOnASingleResource`, `TestMiddlewareForRefusesAResourceThePathsCannotServe`.
- `mcpguard/limits_test.go`
  - `TestAdmitAccessPerAccountAndPerPerson`: 16 places shared per account (`Admit` and `AdmitAccess` share them), 8 each
    per person; `TestAdmitPerPersonThroughTheApplication`: one person's 9th call is 429, another person's is 200.
  - `TestKnownDeadTokensAreNoFailures` (GK-12), `TestFailuresPerAddressOption`,
    `TestTheMissingAddressHeaderIsLoggedOnce`.
- `mcpguard/headers_test.go` `TestReadBodyDeadline`: a real server and a raw TCP slow body get 408 after the deadline with
  `Connection: close`; a POST and a GET with a long answer are not cancelled. Mutation-checked: without the lift, the
  GET case fails (Go clears the deadline itself at the end of a POST body, so a POST alone would not catch it).
- `httpsec/plumbing_test.go`: `TestBodyLimitDeadline`, `TestBodyLimitKeepsItsBytes`, `TestBodyDeadlineWithoutDeadlines`,
  `TestLoopbackPeers`, `TestMountClean`.

The harness uses `ClientIP` `remote`, a fake clock, a guest with a one-hour term and permissions, a guest whose term
ended, and a validator that can answer "known dead" for chosen tokens.

## `auth` and `adminsock`

New tests in `auth/access_test.go` unless noted:

- `TestInviteAccessIsCopied`: the term and permissions reach the person; a failure after `Consume` rolls back (no
  person, the invite reusable); invites without access leave both nil.
- `TestIssueInviteWithAccessRefusals`: an owner with a term or permissions, an ended term, a setup invite, an unknown kind.
- `TestConcurrentRedeem`: two begun ceremonies on one invite finish concurrently; one 200, one 404; the second `Consume` is
  `core.ErrUsed`; exactly one person.
- `TestTermEndsTheSession`: a millisecond before the end all is well; at the end 401 and the session row is gone; sign-in
  is 403 `access_ended` with the exact bytes pinned, no session and no `auth.login.fail`; `SetAccess` later makes
  sign-in work again.
- `TestInviteTermEndedBeforeUse`: the term ends during the ceremony; finish is 404 and the invite stays unused.
- `TestCoOwnerInvite`: a second `RoleOwner`, not a superadmin, in the same account, one account only; an owner-less
  account is still renamed; a store error in the owner check is 500.
- `TestIssueSetupLink`, `TestIssueSetupLinkTTL`, `TestSuperadminCanSignIn`: the link and its 15 minutes, the audit with
  `via=in-process`, older links revoked, refusal once the superadmin has a passkey, allowed after a reset, a failing
  transaction surfaces; a shorter life is the real end in the store, the return value and the audit.
- `TestAdminCommandsNameTheirPeer`: the peer in the audit details and logs; `peer_chain` is there when the peer has a
  chain and absent when it has none; `OnAccessReset` gets the time, the people and the peer, and is not called on a
  failed reset.
- `TestSweepPurges`: `Purger` is called with now; the stats and an error are logged; the first sweep runs at start; a plain
  store is untouched.
- `TestAppWord`: the default "hub" bytes and a custom noun in all five texts.
- `auth/module_test.go`: `TestNew` (a trailing slash, plain http on a public host, an empty or unknown `ClientIP` fail
  `New`), `TestWiring` (over a real socket the audit's `peer_pid` is the test process and its `peer_chain` starts with
  the test's parent).
- `adminsock/adminsock_test.go`: `TestCommandsSeeTheirPeer` (a real socket: uid, pid, executable and chain of the test
  process, the log line, a `Handler` without a socket gets a zero peer) and `TestPeerConnCloseWrite`.
- `adminsock/ancestry_test.go` (review R-5): `TestAncestry` runs the chain over fake process tables (three ancestors at
  most, a parent that is gone or has no name ends it, pid 0, a loop, a process that is its own parent, a container CLI
  with ppid 0); `TestParseProcStat` reads `/proc/<pid>/stat` lines, including a command name with spaces and
  parentheses; `TestPeerChainOfThisProcess` reads the real chain of the test process (on macOS, under `go test`: the go
  command, then whatever started it) and checks that the first link is the parent and every absolute path exists.

The Linux peer code is compiled (`GOOS=linux go vet ./...`, `GOOS=linux go test -c ./adminsock/`) and linted
(`GOOS=linux make lint`) but not executed on this platform; its parsing of `/proc/<pid>/stat` is tested on every
platform through `TestParseProcStat`.
`TestSetupLinkCommand` pins the socket command's output byte for byte.

  nulls are accepted, and the new fields are refused with exact bodies (a term: 400 `invalid`; `permissions`, also

## `tunnel/cloudflare`

All tests run against a fake `cloudflared` built once in `TestMain` from `tunnel/cloudflare/testdata/fakecloudflared`;
the real binary is never run and Cloudflare is never contacted. The fake is steered by files in a `control/` directory
next to its copy (it can release or fail the login, skip the certificate, fail the create, die on demand, exit at once,
serve no metrics, print no URL, or never register) and records every run (arguments, environment, the entries of
`HOME`, its pid) in `control/runs.jsonl`. The backoff is observed through an injected timer and a fake clock, so the
tests contain no sleeps; the one wait is the bounded "nothing happens" window of `TestSupervisorQuickNeedsTheOutput`.

- `start_test.go` (`Connector.Start`): the login link is surfaced before the flow ends; the failing step for each step;
  the refusals; cancelling; `ErrDNSRecordExists`. The old `Connect` tests are unchanged and `Connect`'s output is the
  same.
- `supervisor_test.go`: exact named and quick arguments; the environment is exactly `HOME` and `PATH` (a canary variable
  does not reach the child); the private `HOME` is emptied at every restart; a restart when the child dies; the backoff
  1, 2, 4 to 60 and 60 seconds, reset after a stable run; the probe states; the `api.` host is ignored; `OnURL` fires
  for each new host; no secret in the arguments; `Stop` kills the child; start errors; option validation (including a
  non-loopback metrics address).
- The quick host (review R-6): `TestSupervisorQuickReadsTheHostnameFromTheOutput` (the host from the output, the
  metrics server's confirmation logged, again after a restart), `TestSupervisorQuickWithoutMetrics` (the output alone
  is enough; "did not confirm" is logged), `TestSupervisorQuickIgnoresAnotherProgramOnTheMetricsPort` (a test server
  holds the `--metrics` port and claims `other.trycloudflare.com`: only the printed host is announced and in the
  status, the mismatch is logged at warn), `TestSupervisorQuickNeedsTheOutput` (the fake prints no URL but its metrics
  server names one: after that server answers, 200 ms pass with no `OnURL`, no URL and the state still starting).
- `cloudflare_test.go` (review R-14): `TestConfigQuotesTheCredentialsPath` connects with a tunnel directory named
  `my data: it's #1` and checks the quoted line and, through `assert.YAMLEq`, that a YAML parser reads the exact path
  back; `TestYAMLQuote`; `TestConnect` pins the quoted bytes.
- Not covered: a real cloudflared, and the real field names of `/quicktunnel`, which come from Cloudflare's source.

## UI package

`npm test` runs the Vitest suite. It also passes with `TZ` set to UTC,
`America/Los_Angeles` and `Pacific/Auckland`, because terms end at local end of day.

- `ui/src/lib/access.test.ts`: the presets, the month clamp (31 January becomes 28 or 29 February), the date bounds
  (today to today plus 364 days, under the server's year), refusals, the permission mapping and grouping, and the
  detection of an inactive person.
- `ui/src/features/account/access.test.tsx`:
  - **No catalog:** no pickers, the body is exactly `{name}`, and a tap still opens the remove alert.
  - **With a catalog:** the ticks and a preset send `{name, permissions, access_until}`; nothing ticked is refused
    before any call; «Навсегда» sends `["all"]` with no end; a last day sends that day's end.
  - **coOwners:** the superadmin's «Совладелец» hides the pickers and sends `{name, role: "owner"}`; an owner who is not
    the superadmin gets no role picker, and no change or remove buttons for the superadmin.
  - **An expired person:** greyed with «Продлить»; the `PATCH` gets 403 `step_up_required`, the step-up sheet appears, and
    the same `PATCH` is sent again.
  - **Member detail:** the titles, the term, only this person's connections, «Закрыть доступ сейчас» sends
    `{access_until: now}`; the editor sends only the touched fields.
  - `singleAccount` renders nothing and fetches nothing; `live` defaults to `sse` and follows the prop.
- `ui/src/features/onboarding/coowner.test.tsx`: `co_owner: true` gives the co-owner welcome, three steps and a register
  body of `{token, name}`.
- `ui/src/features/auth/signin.test.tsx`: `access_ended` shows the ended-term text; a plain 403 `forbidden` (even with
  the same message) and the 400 `invalid` keep the generic failure text.

An application that does not pass a catalog renders and sends exactly what it did before: this was checked by rendering a
Mongo-backed deployment's screens with the old and the new package and comparing the screenshots byte for byte, except
for screens whose mock data is random or clock-relative.
