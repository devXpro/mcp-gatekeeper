# G3 — how auth and adminsock are tested

```sh
make -C <repo> lint test PKGS="./auth/... ./adminsock/..."
GOOS=linux go -C <repo> vet ./auth/ ./adminsock/    # SO_PEERCRED
GOOS=windows go -C <repo> build ./adminsock/        # peercred_other.go
```

No Docker, no network, no browser: everything runs in-process with `go test -race`. Coverage: auth 95 %,
adminsock 91 %.

## auth

- **Passkeys** come from a virtual authenticator (`github.com/descope/virtualwebauthn`): `device.create` and
  `device.get` answer the options exactly as `navigator.credentials.create/get` would, so every ceremony runs the
  real go-webauthn verification. Spoiled devices (wrong origin or RP ID, no user verification or presence, a changed
  backup flag, a counter that goes backwards) cover the refusals.
- **The store** is `fakeStore` (`fakestore_test.go`), Family Hub's fake on the gatekeeper's `store.Store`:
  transactions travel in the context, a call made with a context outside the running transaction waits for its lock
  (so forgetting the transaction's context hangs the test instead of passing), `setReplay` runs every transaction
  twice as the MongoDB driver may, and `setFail("<Store>.<Method>", err)` fails any method.
- **Family Hub's legacy keys** are no longer auth's: the fake keeps them beside the gatekeeper's data and
  `legacyStep` is the `ResetStep` Family Hub's adapter (G9) passes. `TestResetAccessEndsConnectorsKeysAndInvites`
  runs reset-access with it unchanged from Family Hub (counts, rollback on every failure, replay).
- **HTTP** goes through a real `*http.ServeMux` with `RegisterRoutes` plus four probes behind `RequireViewer`,
  `RequireStepUp` and `SameOrigin`. A `browser` keeps the cookie and sends what the SPA sends (`X-Family-Hub: 1`,
  `Origin`, `CF-Connecting-IP`, a User-Agent). Gin test contexts became `httptest` requests on the middlewares.
- **Logs** go to `internal/testlog`; `env.logged(msg, key, value…)` replaces Zap's observer filters.
  `TestNoSecretInLogsOrAudit` collects every cookie, link token and challenge a full run saw and searches every log
  record (message and attributes) and every audit entry for them, raw and as the hex of their sha256.
- **The clock** is fake (`clock.Add`), so TTLs, idle and absolute session ends, step-up windows, rate-limit refills
  and the coalesced `auth.login.fail` minute are exact, without sleeps.

New tests beside the ported ones: `TestWiring` (auth on an admin socket shared with an application's own command,
the CLI with Family Hub's names, the routes on a mux, a second Auth refused by the registry), `TestNew` (brand and
reset-step validation), `TestProductName` (the relying party's name is `Brand.Product`),
`TestResetAccessWithoutSteps` (Homie's wording), `TestResetStepRunsInTheTransaction`, and the transaction case of
`TestIssueInviteChecks` for both `IssueInvite` and `IssueInviteIn`.

## adminsock

- Real unix sockets under `/tmp` (macOS limits `sun_path` to 104 bytes; `t.TempDir()` is too long there).
- `peerListener` with a swapped uid lookup refuses a stranger and admits the own user; the real `peerUID` is checked
  on a socket pair.
- Output streaming (`TestOutputStreams`), cancellation at Stop, stale and live sockets, a server that answers
  nonsense, the 1 MiB request cap, a handler that panics (500 without the panic's value in the log).
- The registry: name rules, all-or-nothing `Add`, commands added after `Start` (`TestCommandsAddedLater`).
- `CLI`: Family Hub's exact texts with `Prog: "hub admin", App: "hub", Hint: …`, and neutral defaults.
