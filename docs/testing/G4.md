# G4 — OAuth authorization server tests

Package: `oauth`. Every test is a unit test: the store, the sessions, the resource catalog, the client metadata
fetcher and the clock are fakes in the package (`fakes_test.go`), the logger is `internal/testlog`, so nothing needs
Docker or the network. No test fetches a real client ID metadata document; `TestHTTPFetcher` talks to an `httptest`
TLS server only.

```sh
make -C <repo> lint test PKGS=./oauth/...
```

The golden files of the metadata documents are in `oauth/testdata/`. `authorization-server.json` and
`protected-resource-notes.json` are Family Hub's own files, copied unchanged: they prove the documents did not
change. After a deliberate change, rewrite them and review the diff:

```sh
go -C <repo> test ./oauth/ -run 'Metadata' -update
```

## The fakes

- `fakeStore` answers like the store adapters (`store.Store`): `Tx` rolls back when `fn` fails, a `Tx` inside a `Tx`
  joins it (the transaction travels in the context), and transactions run one at a time; `PutGrant` of a second
  active grant of one (person, client, resource) is `ErrConflict`; `ConsumeCode` deletes an expired code and answers
  `ErrExpired`; `UseRefresh` answers `ErrUsed`, `ErrNotFound` or `ErrExpired` as Family Hub's Mongo store does;
  `RevokeFamily` and the audit's `Append` fail on a cancelled context. `failWith` makes a method fail, once or always.
- `fakeSessions` implements `core.Sessions`: it signs a request in by the cookie `fh_test` (Alice and Bob of the
  Millers, Carol of the Friends), keeps the contract of `RequireViewer` (on a write, the CSRF checks with Family Hub's
  `X-Family-Hub` header come before the session), and gives every session a fresh step-up until a test makes it
  stale.
- `fakeCatalog` implements `core.ResourceCatalog`: notes and photos can be connected and are on for the
  Millers, old cannot be connected (a stopped module), secret is on only for the Friends.
- The harness uses Family Hub's brand (`__Host-fh_txn`, `X-Family-Hub`, "Family Hub") and paths
  (`core.PerResource{Prefix: "/mcp/"}`), so the tests double as the parity check; `single_test.go` runs the flow
  with `core.SingleResource{At: "/mcp", ID: "home"}`.

## Every OAuth error code the package sends

| Code | Endpoint | Test |
|---|---|---|
| `invalid_request` | authorize, token, revoke | `TestAuthorizeRedirectsErrors`, `TestTokenRequestFormat`, `TestClientAuthentication`, `TestRevokeRefusals` |
| `unsupported_response_type` | authorize | `TestAuthorizeRedirectsErrors` |
| `invalid_scope` | authorize | `TestAuthorizeRedirectsErrors` |
| `invalid_target` (RFC 8707) | authorize, token | `TestAuthorizeRedirectsErrors`, `TestExchangeCodeRefusals`, `TestRefreshResource`, `TestSingleResource*` |
| `access_denied` | deny | `TestDeny` |
| `server_error` | authorize, token, register, revoke | `TestAuthorizeServerErrors`, `TestExchangeStoreFailureKeepsTheCode`, `TestRegisterStoreFailure`, `TestRevokeRefusals` |
| `temporarily_unavailable` | register, token, revoke (429) | `TestRegisterRateLimit`, `TestTokenRateLimit`, `TestT2R_TokenTotalBucketDoS` |
| `invalid_client` | token, revoke | `TestClientAuthentication`, `TestClientAuthenticationBadBasicEscape`, `TestRevokeRefusals` |
| `invalid_grant` | token | `TestExchangeCodeRefusals`, `TestCodeExpires`, `TestCodeReuseRevokesItsTokens`, `TestRefreshRefusals` |
| `unsupported_grant_type` | token | `TestTokenRequestFormat` |
| `invalid_redirect_uri`, `invalid_client_metadata` | register | `TestRegister`, `TestRegisterTooLarge`, `TestRegisterBytes` |

`unauthorized_client` is never sent: every client may use both grant types. `unsupported_token_type` is never sent:
revoke knows both kinds of token.

## Not here

- Family Hub's `config_test.go` (the `FH_*` variables, their defaults and the refusal of unknown values) and
  `module_test.go` (the Fx wiring) test code that stays in Family Hub: the gatekeeper reads no environment and has no
  Fx. Card G9 moves them with that code.
- The routing layer's answers to wrong methods, `HEAD`, unclean paths and trailing slashes belong to the
  `http.ServeMux` the application mounts (`TestAuthorizeWrongMethods` only pins that the mux sees the methods).
