## The suite for adapter authors (G2)

```go
storetest.Run(t, func(t *testing.T, cascades ...store.Cascade) store.Store { /* fresh empty store; t.Cleanup closes it */ })
```

The semantics it pins are in the package comment of `store/storetest/storetest.go`. Points an adapter must get right
that the frozen interface does not spell out:
- account delete calls `Cascade.DeletePerson` for every person of the account, then `Cascade.DeleteAccount`, all inside
  the delete's transaction (Family Hub needs the per-person call to delete its legacy keys);
- a reader outside an open transaction must not see its writes and must not wait for it (TxIsolation);
- an audit cursor that is not an id of the adapter's form is an error; limit <= 0 is 50, above 1000 is 1000;
- `Recorder.Calls()` dedups, because a store may run a transaction again.

## For G9 (Family Hub on the gatekeeper)

```go
s, err := mongostore.Open(ctx, mongostore.Options{DB: client.Database(cfg.Database), Cascades: []store.Cascade{fhCascade}, Logger: slogger})
s.Database() *mongo.Database                       // Family Hub's own collections live here
mongostore.EnsureCollection(ctx, db, name, indexes...)  // idempotent; call at start for modules, account_modules, legacy_keys
mongostore.InTx(ctx) bool                          // ctx carries a session with a running transaction
s.Tx(ctx, func(ctx context.Context) error)          // ctx carries the session: Family Hub's own collection calls with it join
```

- Family Hub's three collections and their exact index specs (from `testdata/familyhub/indexes.*.json`):
  `modules` (only `_id`), `account_modules` `{account_id: 1}` and `{module_id: 1}`, `legacy_keys` `{module_id: 1}` and
  `{person_id: 1}`, all with default names and no options. On the live database they exist already, so
  `EnsureCollection` with these specs is a no-op.
- `schema_migrations` now belongs to the gatekeeper (versions 1 and 2 keep Family Hub's names, so the live database
  migrates nothing). Family Hub must not record its own migrations there.
- Family Hub's cascade must do what its store did inline: on `DeletePerson`, delete `legacy_keys` with that
  `person_id`; on `DeleteAccount`, delete `account_modules` with that `account_id` and `$pull` the id from
  `modules.visibility.accounts`.
- With `Options.DB`, `Close` does not disconnect the shared client; AppName and timeouts come from Family Hub's client
  (Family Hub sets app name "family-hub", server selection 10s, op timeout 30s).
- `Tx` gives a context, not a store: Family Hub code that did `st.Tx(ctx, func(tx core.Store) error {...})` becomes
  `st.Tx(ctx, func(ctx context.Context) error {...})` and keeps calling `st` with that ctx.
- `OAuthStore.RevokeGrantsByModule` is now `RevokeGrantsByResource`; `Grant.ModuleID` is `Grant.ResourceID`; the
  document field stays `module_id`.
